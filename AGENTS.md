# AGENTS.md — AI Coding Agent Instructions

This file is the authoritative guide for AI coding agents (OpenAI Codex, Claude, Cursor, etc.) working on the **MICM Maturity Hub** repository. Read it fully before making any changes.

---

## Project at a Glance

Full-stack manufacturing maturity assessment platform.

- **Backend**: Express 5 API at `artifacts/api-server/`
- **Frontend**: React + Vite SPA at `artifacts/micm-platform/`
- **Database**: PostgreSQL with Drizzle ORM, schema at `lib/db/src/schema/`
- **API contract**: OpenAPI spec at `lib/api-spec/openapi.yaml` — this is the single source of truth
- **Generated code**: `lib/api-client-react/` and `lib/api-zod/` are auto-generated — **never edit them directly**
- **Monorepo**: pnpm workspaces; packages use the `@workspace/` prefix

---

## Before You Start Any Task

1. Run `pnpm run typecheck` and confirm it exits cleanly
2. Read the relevant section of `README.md` for context on the area you are changing
3. If the task touches the API contract, read `lib/api-spec/openapi.yaml` before editing

## Critical Rules

### Never edit generated files
These paths are auto-generated by Orval from the OpenAPI spec. Any manual edits will be overwritten on the next codegen run:
- `lib/api-client-react/src/generated/`
- `lib/api-zod/src/generated/`

### API-first development
All new API endpoints must be defined in `lib/api-spec/openapi.yaml` **before** implementing the route handler. After editing the spec, always run:
```bash
pnpm --filter @workspace/api-spec run codegen
```
Then verify `lib/api-zod/src/index.ts` contains exactly:
```ts
export * from "./generated/api";
```
(Codegen sometimes adds extra exports — remove them.)

### Never use console.log in server code
Use `req.log` inside route handlers and the singleton `logger` from `artifacts/api-server/src/lib/logger.ts` for non-request code. `console.log` is stripped in production builds.

### Never add relative cross-artifact imports
`artifacts/` packages must not import from each other. Put shared code in a new `lib/` package.

### Never run `pnpm dev` at the workspace root
There is no root `dev` script by design. Run each service individually:
- `pnpm --filter @workspace/api-server run dev`
- `pnpm --filter @workspace/micm-platform run dev`

### Never call `setBaseUrl("/api")` in the frontend
Orval bakes `/api` into every generated hook path. Calling `setBaseUrl("/api")` would double-prefix every request to `/api/api/…`. Only set the base URL to the sub-path prefix if the app is not mounted at root.

### Do not disable `minimumReleaseAge` in pnpm-workspace.yaml
This setting (1440 minutes) is a supply-chain attack defence. Do not set it to 0 or remove it.

## Adding a New API Endpoint — Step by Step

1. Add the path and operation to `lib/api-spec/openapi.yaml`
2. Run `pnpm --filter @workspace/api-spec run codegen`
3. Fix any typecheck errors in the generated types
4. Create or extend a route file in `artifacts/api-server/src/routes/`
5. Register the router in `artifacts/api-server/src/routes/index.ts` if it is a new file
6. Use the generated Zod schema (from `@workspace/api-zod`) to validate the request body and shape the response
7. In the frontend, import the generated React Query hook from `@workspace/api-client-react`
8. Run `pnpm run typecheck` and confirm clean

---

## Adding a New Database Table — Step by Step

1. Create or edit a file in `lib/db/src/schema/`
2. Export the table and its insert schema from `lib/db/src/schema/index.ts`
3. Run `pnpm --filter @workspace/db run generate`
4. Review and commit the generated SQL in `lib/db/migrations/`
5. Apply migrations locally with `DATABASE_URL=<local_dev_url> pnpm --filter @workspace/db run migrate`
6. Export the table from `lib/db/src/index.ts` if route handlers need to import it
7. Run `pnpm run typecheck`

## Roles

Three roles exist in the `users.role` column:

| Value | Meaning |
|---|---|
| `super_admin` | Full platform access; cross-company visibility |
| `company_admin` | Own company only; can manage assessments and users |
| `company_user` | Own company only; can take assigned assessments |

Tenant isolation is enforced in route handlers — always filter queries by `companyId` for non-Super-Admin users. Failing to do so is a data leak.

## Score Scale

Assessment criteria are scored 0–4:

| Score | Meaning |
|---|---|
| 0 | Traditional Baseline criteria followed |
| 1 | At least 25% of processes in place / operational areas covered |
| 2 | At least 50% of processes in place / operational areas covered |
| 3 | At least 75% of processes in place / operational areas covered |
| 4 | Excellence criteria met for all areas |

Domain scores on radar charts are the arithmetic mean of all criteria scores for that domain across all completing users.

## Demo Mode

`POST /api/demo/sign-in-token` returns a Clerk sign-in token for one of three hardcoded demo accounts. It is **disabled unless explicitly enabled outside production**:

- `NODE_ENV === "production"` → HTTP 404
- `ENABLE_DEMO_AUTH !== "true"` → HTTP 404
- Frontend demo panel requires `VITE_ENABLE_DEMO_AUTH === "true"` and is hidden in production builds

The hardcoded Clerk user IDs in `demo.ts` are specific to the Replit development Clerk tenant. If you are working against a different Clerk tenant, run `seed-demo-users` and update the `DEMO_USERS` map with the new IDs.

**Never enable demo auth flags in production. Never remove the production guard.**

## Replit-Specific Behaviour

These things are Replit-specific and should not be "fixed" by an agent working outside Replit:

- `REPL_ID` environment variable is used to conditionally load Replit Vite plugins (`@replit/vite-plugin-cartographer`, `@replit/vite-plugin-dev-banner`). These plugins are no-ops outside Replit — the condition is correct.
- `pnpm-workspace.yaml` has Linux-only esbuild and Rollup platform overrides. These are needed for the Replit Linux container. **Do not remove them when working in Replit.** If developing on macOS/Windows, comment them out locally — do not commit that change.
- `.replit` configures Replit workflows, ports, and deployment — it is safe to commit and should not be modified unless you understand the Replit platform configuration.
- `artifacts/*/.replit-artifact/artifact.toml` files define service routing. Do not edit port numbers or paths without understanding the proxy configuration.

## TypeScript Conventions

- All `lib/` packages are **composite** (emit declarations via `tsc --build`)
- All `artifacts/` packages are **leaf** (checked with `tsc --noEmit` only, never emit)
- Do not add leaf packages to the root `tsconfig.json` references array
- The canonical typecheck is `pnpm run typecheck` at the workspace root — trust it over editor LSP state
- `as any` casts on `enabled` in TanStack Query options are intentional — TanStack Query v5 requires `queryKey` in `UseQueryOptions` but Orval provides it internally

## Gotchas and Known Issues

- **Codegen sometimes adds extra exports to `lib/api-zod/src/index.ts`** — after every codegen run, verify the file contains only `export * from "./generated/api";`
- **Clerk `routing="path"` + Wouter**: the `path` prop on Clerk's `<SignIn>` / `<SignUp>` must be the full browser path including `BASE`. Wouter's `<Redirect>` strips the base automatically.
- **Migration baseline required for existing environments**: schema changes must use generated migrations. Existing databases that predate migration history need the initial baseline migration marked as applied before running new migrations.
- **`PORT` and `BASE_PATH` are required** at both API server and Vite startup — they are injected by Replit workflows. Set them in your shell when running locally.
- **esbuild platform overrides** in `pnpm-workspace.yaml` strip all non-Linux native binaries. `pnpm install` will fail on macOS/Windows unless these overrides are commented out.
- **Standard questions** — domains/categories remain fixed. Only Super Admins may edit the global criteria catalogue through `/api/standard-assessment-questions`. Removal uses `criteria.is_included=false`, never deletion. New assessments copy included criteria; existing snapshots/answers must not change. Never use re-seeding to update an existing catalogue.
